### 1. Feature Overview

The Drafts & Briefs feature within Work Studio enables users to author working documents with AI assistance and generate structured summary briefs from existing platform content. Drafts are user-authored documents refined with Akki. Briefs are Akki-generated read-only artefacts produced from selected source documents. Both live in a single shared list, follow a Draft-to-Committed lifecycle, and are accessible through a consistent side drawer experience.

### 2. Feature Objective

Enable users to create, refine, and finalise governance documents and structured briefs within a single workspace — reducing the effort required to produce board-ready written content while keeping the user in full control of what gets committed and published.

### 3. Feature Goals

Provide a dedicated authoring environment where users write and refine documents with AI assistance

Enable users to generate structured briefs from one or more platform documents

Surface document intelligence and signals to inform decision-making before committing

### 4. User Experience

4.1 Drafts & Briefs List

The Drafts & Briefs workspace displays all documents in a single scrollable list — no pagination. New cards always appear at the top. The list has a search box for filtering by keyword and a sort control defaulting to Most Recent.

Two tabs sit at the top of the list:

Active tab — the default view. Shows all Draft and Committed documents. This is the user's primary working list. Search and sort apply within this tab.

Archived tab — shows only Archived documents, fully separated from the active working list. The same card spec, search, and sort apply. The user navigates here when they need to retrieve a previously archived document. Documents can be unarchived from this tab, returning them to the Active list with their Committed badge intact.

Draft card displays:

Document title

Draft badge

Creation date and last edited date

Created by you label — persists in both Draft and Committed states

Brief card displays:

Document title

Draft badge + Akki Generated badge — before commit

Committed badge + Akki Generated badge — after commit

Creation date

Number of source documents

Confidence score

Clicking any card opens the corresponding side drawer.

4.2 Create Draft Journey

The user selects New Draft. A modal appears with two required fields:

Title — the name of the document.

Goal — a plain-language statement of what the document is meant to achieve. The goal is locked after the draft is created and cannot be changed. It appears as a read-only reference field in the Intelligence tab throughout the document's lifetime.

Selecting Save and Start Drafting closes the modal and opens the Draft side drawer.

4.3 Draft Detailed View — Side Drawer

The drawer occupies three quarters of the screen. The header, tab bar, and footer are fixed. The document content area scrolls independently.

Header — Draft state:

Draft badge

Akki Generated badge — only shown if the draft was seeded from an existing document

Document title — inline editable at all times in Draft state. The user clicks the title, types, and confirms with Enter or by clicking away. The card in the list updates immediately

Creation date and last edited date

Delete icon — top right, adjacent to the close icon. Clicking triggers a confirmation modal: "Delete this draft? This cannot be undone." Two options: Delete and Cancel. Available in Draft state only

Close icon — top right

Header — Committed state:

Committed badge

Akki Generated badge — only shown if applicable

Document title — static label. No longer editable

Creation date and last edited date

Archive icon — top right, adjacent to the close icon. Clicking triggers a confirmation modal: "Archive this document? It will no longer appear in your active list." Two options: Archive and Cancel

Close icon — top right

Tab bar: Document, Intelligence, Your Notes, Signals, Related Documents

Footer — Draft state:
Use in Solva, Use in Chat, Test Hypothesis, Share Document, Commit. Commit sits rightmost and is the most visually prominent action — dark filled button.

Footer — Committed state:
Use in Solva, Use in Chat, Test Hypothesis, Share Document, Download. Commit is absent.

4.4 Draft — Document Tab

The Document tab is the primary authoring surface. A DRAFT watermark is visible across the document area at all times in Draft state — a persistent visual signal that the document is not yet final. The watermark is absent in Committed state.

Editing:

The user clicks Edit to activate the document input area. A formatting toolbar appears above the document providing Bold, Italic, and Underline. The user types and formats content. Formatting renders visually — not as raw syntax. The document autosaves continuously while the user types. The user clicks Save or clicks outside the document area to exit edit mode.

The user can reverse a direct edit using Ctrl+Z / Cmd+Z.

Prompt-Based Edit:

The Prompt-Based Edit section sits below the document content and is reached by scrolling. It contains a single-line input field with placeholder text: "e.g. rewrite section 2 to be sharper" and an Apply button.

The user types a plain-language instruction and clicks Apply. A loading state appears while Akki processes. Akki rewrites the entire document based on the instruction. The proposed rewrite appears in a Proposed Rewrite panel directly below the input. Both the original document and the proposed rewrite are visible and independently scrollable simultaneously. A diff character count is shown in the top right of the proposed rewrite panel.

An inline warning sits adjacent to the Apply CTA within the proposed rewrite panel: "Applying replaces your document. Use Undo to reverse if needed."

Two CTAs sit below the proposed rewrite: Apply and Discard.

Apply — replaces the document content with the proposed rewrite. The user can reverse this using Ctrl+Z / Cmd+Z which restores the document to its state immediately before the rewrite was applied. One level of undo only — the user can reverse the most recently accepted rewrite but cannot step back through multiple previous rewrites

Discard — dismisses the proposed rewrite. The document content remains unchanged

Only one prompt-based edit can be active at a time. The user must Apply or Discard before submitting another prompt.

After a prompt-based edit is applied, intelligence and signals do not update automatically. The user must navigate to the Intelligence tab and manually trigger a refresh.

In Committed state the document area is read-only. The Edit button is absent. The Prompt-Based Edit section is absent. Undo is absent.

4.5 Draft — Intelligence Tab

The user clicks Generate Intelligence. A loading state appears. The system analyses the document and returns:

What This Is — a plain-language summary of the document

Goal Assessment — an evaluation of whether the document content has met the goal set at creation. The original goal appears as a read-only reference at the top of this section

Clarity Signals — word count, average sentence length, jargon density

Provenance — origin and source information

The user can regenerate intelligence at any time. Regenerating does not change the document. Generating intelligence also populates the Signals tab.

4.6 Draft — Your Notes Tab

A private free-text notes area for personal annotations. Notes autosave after every keystroke with a one to two second debounce delay. A "Saved just now" indicator below the notes area confirms each save. Notes are private and do not affect the document content.

On returning to the tab — whether in the same session or a future one — notes are exactly as last saved.

The user can undo note edits using Ctrl+Z / Cmd+Z and redo using Ctrl+Shift+Z / Cmd+Shift+Z within the active session. The edit history clears when the session ends but the last saved content always restores.

If autosave fails the indicator changes to "Save failed. Retrying…" The user can keep typing — the system retries automatically.

Notes remain editable in both Draft and Committed states.

4.7 Draft — Signals Tab

Signals appear here after the user generates intelligence in the Intelligence tab. The tab shows risks, opportunities, and recommendations identified from the document content.

Signals are private to the user and do not feed into Pulse while the document is in Draft state. When the user commits the document, signals feed into Pulse automatically.

4.8 Draft — Related Documents Tab

Displays documents connected to the draft across four categories: Same Metadata, Explicit Attachment, Canonical Lineage, and Content Similarity. The user can manually attach a related document using the "+ Attach related document" link.

4.9 Draft — Commit Flow

The user clicks Commit in the footer. A confirmation modal appears: "This document will be locked. No further editing will be possible." Two options: Confirm and Cancel.

On confirm:

The drawer closes

The card in the list updates — Draft badge changes to Committed badge. Created by you label persists

The document is locked and read-only

Signals feed into Pulse automatically

The DRAFT watermark disappears

Commit is absent from the footer on reopening

Download appears in the footer

Archive icon replaces Delete icon in the header

4.10 Draft — Delete

The user clicks the Delete icon in the header. A confirmation modal appears: "Delete this draft? This cannot be undone." Two options: Delete and Cancel. Deletion is permanent. Available in Draft state only.

4.11 Draft — Archive

The user clicks the Archive icon in the header of a committed document. A confirmation modal appears: "Archive this document? It will no longer appear in your active list." Two options: Archive and Cancel.

On confirm the document moves to the Archived tab. It carries an Archived badge. The user can unarchive from the Archived tab — the document returns to the Active list with its Committed badge intact.

4.12 Generate Brief Journey

The user selects Create a Brief. A single modal opens showing all inputs simultaneously.

Brief definition fields:

Description — what the brief is about

Objective — what the brief is meant to achieve. Locked after generation. Appears as a read-only reference in the Intelligence tab. To produce a brief with a different objective the user creates a new brief — source documents are already in the system so reselection is fast

Scope — what is included and what is not

Source document selection:

A searchable list of platform documents sorted alphabetically with an inline search bar above the list. The user selects one or more documents. Each selected document appears as a removable tag below the list.

The Compose button sits at the bottom of the modal and remains inactive until all three fields are completed and at least one document is selected.

Clicking Compose triggers a progress modal showing each generation step completing sequentially. A toast notification confirms generation is in progress.

On completion three options appear: Download, Continue in Chat, Close.

A new Brief card appears at the top of the Active list with a pulse animation, carrying Draft and Akki Generated badges. The Brief side drawer opens automatically.

4.13 Brief Detailed View — Side Drawer

The drawer occupies three quarters of the screen. The structure mirrors the Draft side drawer with the following differences.

Header — Draft state:

Draft badge + Akki Generated badge

Document title — inline editable. Updates card immediately

Creation and last edited dates

Delete icon — top right. Same confirmation as Draft delete

Close icon

Header — Committed state:

Committed badge + Akki Generated badge

Document title — static label. No longer editable

Creation and last edited dates

Archive icon — top right. Same confirmation as Draft archive

Close icon

Tab bar: Document, Intelligence, Your Notes, Signals, Related Documents

Footer — Draft state:
Use in Solva, Use in Chat, Test Hypothesis, Share Document, Commit.

Footer — Committed state:
Use in Solva, Use in Chat, Test Hypothesis, Share Document, Download. Commit is absent.

4.14 Brief — Document Tab

The user reads the generated brief as formatted rich text. The document is read-only in all states. There is no Edit button. There is no Prompt-Based Edit section. The DRAFT watermark is visible in Draft state and absent in Committed state.

4.15 Brief — Intelligence Tab

The user clicks Generate Intelligence. The system analyses the brief and returns:

What This Is — a plain-language summary of the brief

Objective — the read-only objective set at creation, shown as a reference at the top of this section

Clarity Signals — word count, average sentence length, jargon density

Provenance — origin shown as Akki Generated, source shown as Drafts & Briefs

Sources — the documents used to generate the brief, listed by name

Generating intelligence also populates the Signals tab. The user can regenerate at any time without changing the brief content.

4.16 Brief — Your Notes Tab

Identical to Draft Your Notes. Private, autosaves continuously, persists across sessions, editable in both Draft and Committed states.

4.17 Brief — Signals Tab

Signals appear after the user generates intelligence. Risks, opportunities, and recommendations identified from the brief content.

Signals do not feed into Pulse in Draft state. On commit they feed into Pulse automatically.

4.18 Brief — Related Documents Tab

Identical structure to Draft Related Documents — Same Metadata, Explicit Attachment, Canonical Lineage, and Content Similarity.

4.19 Brief — Commit Flow

Identical to Draft commit flow. On confirm the drawer closes, the card updates to Committed badge with Akki Generated badge retained, the document locks, signals feed into Pulse, Download appears in the footer, and Commit is absent on reopening. The Archive icon replaces Delete in the header.

4.20 Share Document — Magic Link

Available in both Draft and Committed states for both Drafts and Briefs. The user clicks Share Document, enters recipient email addresses, and the system generates and sends a magic link.

Recipient scenarios:

Existing platform user — the magic link authenticates them and opens the document in the side drawer. Download is available per their normal permissions

Non-platform user — the magic link grants temporary read-only access without requiring account creation. Download is not available. This is a deliberate governance decision — an unauthenticated user downloading board-level content creates an unauditable distribution record. If the sender wants the recipient to have a local copy they download it themselves and forward it

Same user on a different device — the magic link authenticates them and opens the document in the side drawer. Download available

In all cases the shared view is read-only regardless of lifecycle state. The recipient cannot edit, commit, delete, or archive through the shared link.
