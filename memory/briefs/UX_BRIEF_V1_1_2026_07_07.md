## Work Studio – Deck Feature UX Brief

### Version History

| Version | Date | Author | Summary |
|---|---|---|---|
| 1.1 | 7th July 2026 | Product Team | Updated UX Brief for the Deck feature within the Work Studio module. |

Feature Objective

Enable executives and non-executives to create high-quality presentation decks from existing workspace content or their own authored context, refine them through direct editing and AI-assisted prompting, and commit a final version — reducing the time and effort required to produce board-level presentation material without sacrificing user control over the output.

Feature Goals

Enable users to generate presentation decks from existing briefs, uploaded documents, or user-authored context

Provide a rendered artefact view where users can directly edit slide content and prompt Akki to make targeted changes

Surface a diff view for every Akki-proposed change so the user retains explicit control over what is applied

Reduce the effort required to prepare executive presentation materials

Allow users to iteratively refine decks before committing them as final

Support collaboration through download, share, and Chat continuation

Improve document discoverability through source traceability and related documents

Enable enhancement of externally created decks through upload and instruction

User Experience

4.1 Deck List

The Decks workspace displays all deck cards in a single scrollable list — no pagination. New cards always appear at the top. The list has a search box allowing the user to search by keyword and a sort control defaulting to Most Recent.

Each deck card displays:

Row 1: Document icon — Deck title — Status badge(es) — Download icon

Row 2: Creation date · Source count · Confidence score

Three badge combinations are possible on a card:

Draft alone — context has been saved by the user but no deck has been generated yet. Subtitle: Created by User

Draft + Akki Generated — deck has been generated but not yet committed. Subtitle: Akki Generated

Committed + Akki Generated — deck is locked. Document icon shows a lock overlay

Archived + Akki Generated — deck has been archived

Clicking any card opens the Deck Detailed View.

4.2 Create Summary Deck — From Brief or Document

The user clicks Create Summary Deck. A modal opens with two fields:

Title — required. The Create Deck button remains inactive until a title is entered.

Start From — three radio button options:

An existing brief in this workspace — selecting this expands an inline searchable list showing briefs and Akki-generated documents in the workspace. The user can select one or more items. Each selected item appears as a tag below the list

An external document I've already uploaded — selecting this expands an inline searchable list of uploaded documents. A persistent prompt at the bottom reads "Don't see it? Upload now" which opens a file upload modal on top of the current modal. Once uploaded the document is automatically selected. The user can select one or more items

Blank — I'll write it myself — selecting this requires no source selection. The Create Deck button activates on title entry alone

For Brief and Document paths, the Create Deck button activates once a title is entered and at least one source is selected.

Important distinction communicated in the modal: For Brief and Document paths, Akki generates the deck immediately from the selected sources. For Blank, the user is taken to an authoring environment to write context before any generation occurs. This is communicated via a descriptive sublabel beneath each radio option so the user understands what happens next before clicking.

4.3 Generation — From Brief or Document

After clicking Create Deck the modal content transitions to a progress state — a checklist of steps completing one by one:

Reading your sources

Structuring the slides

Drafting the content

A toast notification appears at the top of the screen confirming generation is in progress.

On completion three options appear within the modal: Download, Take to Chat, and Close. Closing the modal returns the user to the Deck list where the new card appears at the top with Draft and Akki Generated badges, entering with a pulse animation before settling.

The Deck Detailed View opens automatically without requiring the user to click the card.

4.4 Create Deck from Blank

Selecting Blank opens a full-page authoring environment immediately — no generation, no waiting. The page contains:

Editable title pre-filled from the modal

A large context input area with placeholder text: "Describe what this deck should cover. Include the audience, the key message, and any data or decisions you want included."

A word count indicator bottom right of the input area

Two CTAs: Save as Draft and Generate Deck

Save as Draft — closes the authoring environment. A Draft card appears in the Deck list with a Created by User subtitle. No Akki Generated badge is shown since no generation has occurred. Clicking this card reopens the authoring environment with the saved context intact. The user can continue editing and save again or generate when ready.

Generate Deck — triggers the same progress checklist modal as the Brief/Document path. On completion the same three post-generation options appear: Download, Take to Chat, Close. The card enters the Deck list with Draft and Akki Generated badges.

4.5 Enhance Deck

The user clicks Enhance Deck in the Decks tab. A modal opens titled "Improve a Deck you already have."

The modal contains:

Source file — a styled file upload control accepting DOCX, PPTX, and PDF files. Once a file is selected a confirmation tile appears showing the filename, file type, and a Remove option

Instructions — a free-text input field with placeholder text: "What should change — e.g. Tighten the executive summary, restructure the flow, update the theme." The user can provide natural language instructions covering content, layout, narrative flow, and visual direction. The Enhance button remains inactive until both a file is uploaded and instructions are provided

Output format — PPTX, PDF, or Auto. Auto matches the output format to the uploaded file type and is the default. The Auto label reads "Auto — matches your uploaded file" to remove ambiguity

Clicking Enhance transitions the modal to a loading state — a checklist of steps completing sequentially. A toast notification confirms enhancement is in progress.

On completion three options appear: Download, Take to Chat, Close.

Closing the modal returns the user to the Deck list. The enhanced deck card appears at the top with a pulse animation, carrying Draft and Akki Generated badges. Clicking the card opens the Deck Detailed View — the same view used for generated decks — with the full rendered artefact, Akki prompt input bar, diff view, direct editing, and commit flow.

4.6 Deck Detailed View

Opening any generated or enhanced deck card navigates to the Deck Detailed View. This view renders the deck as a live artefact — each slide displayed as a distinct visual block showing the slide title, body content, and any supporting points, formatted to resemble a slide. The view is scrollable. This is the primary working surface for review, editing, and refinement.

Header — fixed, always visible:

Close icon — returns user to the Deck list

Deck title — inline editable in Draft state. Clicking the title transforms it into an input field confirmed with Enter or click away. In Committed state the title is a static label

Status badge(es) — Draft / Akki Generated, or Committed / Akki Generated

Sources indicator — shows the number of source documents used, e.g. "3 sources." Clicking expands a sources panel listing each source document by name

Undo — reverses the most recent change whether direct or Akki-applied. Keyboard shortcut Ctrl+Z / Cmd+Z. Active only when there is a change to reverse

Rendered artefact — scrollable:

Each slide is a distinct visual block. The user clicks directly into any slide to edit it inline — the slide becomes an editable surface and the user types directly. No mode activation is required. Changes are applied immediately and the slide returns to read-only display when the user clicks away.

Akki prompt input bar — fixed, sits between the rendered artefact and the footer:

A full-width input field with placeholder text: "Describe what you want to change — e.g. Make slide 3 more concise, add a risks section after slide 5."

Submitting a prompt triggers a loading indicator on the affected slide. Once Akki processes the instruction the affected slide expands vertically into a comparison card:

Original on the left — showing the current slide state including any manual edits the user has made. Manual edits are always treated as the baseline for diff purposes, not the original Akki-generated content

Proposed on the right — showing Akki's suggested revision

Accept and Reject buttons below the comparison card

Accepting applies the proposed change and the slide collapses back to its normal display updated with the new content. Rejecting dismisses the proposed change and the slide returns to its current state unchanged. Only one diff is shown at a time — the user must accept or reject before submitting another prompt.

After an Akki-applied change is accepted, Undo reverses it and restores the pre-change state.

Footer — fixed, always visible:

Four actions sit in the footer: Commit, Download, Share, Delete (Draft state) or Archive (Committed state).

Commit is the most visually prominent — dark filled button. Download and Share are secondary outlined buttons. Delete/Archive sits furthest right, visually separated by a small divider.

Commit flow:

Clicking Commit triggers a confirmation modal: "This deck will be locked. No further editing will be possible." Two options: Confirm and Cancel.

On confirm:

The Deck Detailed View closes

The user lands on the Deck list

The committed card is visible at the top of the list with the Committed and Akki Generated badges and a lock icon overlay on the document icon

The card pulses briefly before settling

Committed state in Deck Detailed View:

Clicking a committed card opens the same Deck Detailed View in read-only mode. The rendered artefact is not editable — clicking a slide does not activate editing. The Akki prompt input bar disappears entirely for committed decks. The rendered artefact area expands to fill the space previously occupied by the input bar, giving the committed deck more visible content area.

The Undo control is hidden. The title is a static label. Commit button disappears entirely from the footer when the deck is committed. The footer for a committed deck shows Download, Share, and Archive only.

Delete — Draft decks only:

Clicking Delete triggers a confirmation modal: "Delete this deck? This cannot be undone." Two options: Delete and Cancel.

Archive — Committed decks only:

Clicking Archive triggers a confirmation modal: "Archive this deck? It will no longer appear in your active deck list." Two options: Archive and Cancel. On confirm the card is removed from the active Deck list and assigned an Archived badge. Archived decks are accessible from a separate Archived filter tab.

4.7 Version Management — Blank Decks

For decks generated from Blank, the Document tab includes a Source Context section at the bottom of the rendered artefact. This section is always visible and displays the original context the user typed to generate the deck.

A single CTA — Edit Context — opens the authoring environment with the original context pre-filled and editable. Two CTAs are available:

Save — saves the updated context without generating a new deck

Generate New Deck — triggers generation using the updated context. A new deck card is created in the Deck list alongside the original, automatically named with the next version number — for example "April ExCo Read-out V2." The original card is always preserved. Each version has its own independent lifecycle, sources, and committed state
